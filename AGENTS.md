# Правила продолжения проекта

## Контекст и цель

Проект создаёт Windows GUI для безопасной настройки MikroTik RouterOS 7 через GitHub Actions и отдельный self-hosted runner. Пользователь просит запускать сборку через GitHub Actions после изменений, документировать их и не создавать дополнительные ветки. Соблюдайте ограничения текущей среды и работайте только в разрешённой ветке; перенос в `main` выполняйте лишь если он разрешён и явно согласован.

## Текущее состояние

- `app/gui.py` — Tkinter GUI, запускающий workflow через GitHub REST API; GitHub-токен не сохраняется на диск.
- `runner/firewall.py` и `.github/workflows/routeros-firewall.yml` — отправка SSH-команды на RouterOS 7 через выделенный Linux self-hosted runner. Создаётся только **отключённое** правило `input` (IPv4, TCP/UDP, accept/drop).
- `.github/workflows/build-windows.yml` — тесты и сборка неподписанного автономного Windows `setup.exe` с помощью PyInstaller; результат — Actions artifact `mikrotik-setup-windows`. Это приложение, не установщик.
- `tests/` — unit-тесты без реального GitHub, SSH и роутера. `README.md` — инструкции по настройке и безопасному тестированию.
- Реальное устройство, Windows GUI и сквозной workflow ещё не были проверены. Не описывайте их как проверенные без подтверждённых результатов.

## Рабочий процесс

1. Перед изменениями изучите `README.md`, `CHANGELOG.md`, код, `git status` и настройки текущей ветки.
2. Для каждого изменения обновляйте `CHANGELOG.md` (что сделано, что проверено, ограничения) и, при необходимости, `README.md` и этот файл. Не записывайте токены, ключи, адреса частных устройств и иные секреты в репозиторий, логи или чат.
3. Запускайте `python -m unittest discover -s tests -v`. После публикации изменений запускайте Windows-сборку через GitHub Actions и проверяйте итог конкретного run, не ограничиваясь фактом отправки. При push изменений в `app/` или workflow сборка стартует автоматически. В остальных случаях, если ручной запуск доступен, используйте `gh workflow run build-windows.yml --ref <текущая-ветка>`; GitHub требует присутствия workflow в default branch для workflow_dispatch. Если ручной запуск недоступен, сообщите об этом и не утверждайте, что сборка прошла.
4. Чтобы проверить результат, используйте `gh run list` и `gh run view <id>`, при необходимости `gh run watch <id>`. Ожидаемый artifact — `mikrotik-setup-windows`. Запускайте и публикуйте только то, что разрешено пользователем и текущей средой.
5. Не делайте опасных изменений на реальном устройстве без согласования, независимого доступа и резервной копии. Создание черновика не означает его включение. Ручной SSH host-key pinning обязателен. Не доверяйте входным данным из GitHub: проверяйте их непосредственно перед формированием команды RouterOS.

## Безопасность

Исходный GitHub-репозиторий на момент подготовки этого файла публичный. Self-hosted runner и secrets для устройства следует использовать только в защищённом приватном репозитории с доверенными ветками; лица с правом менять код workflow и запускать его могут получить secrets. Не запускайте на таком runner непроверенные PR и сторонний код. Подробнее — в `README.md`.
